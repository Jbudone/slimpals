# Audit 6: collaborative authoring tool (2026-11-10)

From a Fable subagent briefed as an AI tools engineer (human-plus-AI creative tooling). It read the content pipeline, review pages, staff-room card and schema; it did not read AdminInbox, ContentPipeline, writersRoom, server storyCouncil, cast, bonds or portraits.

## Why today's tooling cannot iterate (verified)
`/review` is a verdict, not a conversation: no text input (the `note` field exists in `submitReview` but the page never sends it), no edit, a reviewed item never returns. `loadKit` feeds the next batch the last 8 Good and 8 Meh/Bad by recency, not by character (no speaker field) and with no before/after pairs; the batch runs overnight.
`/story-review` iterates only at whole-document level ("send back" rejects the whole arc/outline/scene; nothing can be locked) and reaches players only for campaign 13+. `TextRequest` has no temperature. Every content route is `requireAdmin`, so friends have no way in.
Its inference on the failed samples: all twelve used one mechanism (a clipped deadpan callback to a tic), and a tic is only funny after you have seen it set up; cards written by the agent whose taste already missed repeat the mistake; two-line bubbles between strangers are the hardest format and should come last; a scene from a seed you supply ("this week Brody discovers mouth tape") is far easier because the seed carries half the joke.

## The design: "The Table" (`/table`, phone first)
Loop (5-15 minutes): type a seed + pick format and cast; get six takes, each a different comic angle; react per take (laugh / almost / no, with why chips: don't get it, no joke, not how they talk, too long, mean, seen it); tap a line to edit it; lock lines;
regenerate around locks (locked lines verbatim, checked after generation); Play it in the real staff-room card (`staffRoom.replay`, no records written); Publish; mark canon. Screens: Home (drafts, friend moments, canon, votes), Seed, Takes (swipe), Workshop (locks, reorder, "tell the AI", version history), Canon (People/Gags/Facts, editable), Friends vote page.
Data: `write_pieces` (format, seed, cast, status, lines json with locked/src/model, version, slot), `write_events` (append-only: generated, react, edit, lock, ask, publish, vote, canon, laugh), `write_canon` (person/gag/fact/moment rows; a voice card is a `person` row that fills from kept lines).
Every tap improves the next prompt by retrieval, not fine-tuning: laughed/published pieces become examples (cast and format match first); edits become before->after pairs (newest 6, the strongest signal); "no"+why becomes avoid examples (newest 5); "more like this" pins a lead example; locks are passed verbatim; "tell the AI" is a session instruction; canon raises retrieval rank.
Friends need no token links (they are invited users): a blind vote page, a "laugh/canon" button on a cutscene's last line (two friends promote a proposed gag for the owner to confirm), and a "something funny happened" moments form that appears on the owner's Home as seeds (expected to be the best input).
Published pieces play in the existing card: `getStaffRoomDto` returns a due published piece as `pending` (id `w<id>`), `markEpisodeSeen` already writes the claim; Friday D&D pieces use their own slot (existing `SLOT_DAYS` `[3, 6]` untouched). Add `brody` and `tom` to `SPEAKERS` (a speaker without a face falls back to an initial). Bro Hype overlaps the existing "Fad of the Fortnight" arc, which can retire after Brody has three published scenes.

## MVP (1-2 days), Bro Hype only
Migration `0043_write_table.sql`; `shared/content/table.ts` (pure `assemblePrompt`, `parseTakes`, `locksHeld`); `server/services/content/table.ts`; `server/routes/table.ts`; `temperature` on `TextRequest`; `src/pages/Table.svelte` and `TableVote.svelte`; speakers; the published-piece hook in `server/services/gym/staffRoom.ts`; a laugh button in `StaffRoomCard.svelte`; an inbox card; a changelog entry; `tests/content/table.test.ts`.
Endpoints under `/api/admin/table/...` (pieces, takes, adopt, react, lines, rewrite, per-line alts, publish, canon) plus `/api/table/vote`, `/moments`, `/laugh` for any signed-in user. Prompt: system = ten-line format rule + People + True facts + Running gags; user = seed, cast, kept examples, edit pairs, avoid examples, lead, locked lines, ask, "Write 6 takes, each a DIFFERENT comic angle, name the angle in 6 words", JSON only; temperature 1.0, `reserve: true`, a new `table` route set to the strongest OpenRouter model.
Deliberately left out: judge, critic, cliche gate, reviser, near-duplicate gate, bake-off, auto-written voice cards, banter/D&D/story formats on day one, and no example scenes written by Claude (the example pool starts empty and fills only from what the owner keeps or edits).

## Table vs chatting with Claude
Chat wins for arc planning, bulk rewrites of authored files and arguing structure, and costs nothing today; the Table wins for five-minute phone sessions, instant Play in the card with portraits, stored taste, friends, and shipping a line as a row (no PR or deploy). Risk: if the model's takes are as flat as before the Table is a nicer interface on the same problem; the seed, the owner's edits and a stronger model are what differ. Fallback: Claude writes scenes in chat and commits them as authored episodes.

## Recommended first build and test
The Table MVP for Bro Hype scenes only (the owner defined the premise, a weekly fad is a one-line seed, scenes fit the card player, no data slots). Owner time ~40 minutes: three ridiculous fads and one sentence on what makes Brody funny (5 min); set the `table` model and test the key (2); first session with two seeds, 12 takes, edit, Play, publish (15); a second session next day (15); send friends the vote link (1).
Pass: in session one the owner publishes a scene they would show a friend with fewer than half its lines rewritten; session two has more laugh/almost takes untouched than session one; a friend taps laugh. Fail: two sessions, ~24 takes, nothing worth keeping even after edits: stop generation machinery; the owner or Claude-in-chat write scenes and the Table stays an editor and player.
